# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Hermes Logistics landing site — Nuxt 4 + TypeScript + Tailwind CSS. Single-page: there is no `app/pages/` directory; the entire page is composed in `app/app.vue`, which stacks the section components in order and owns the contact-modal open state.

## Commands

Always use `bun` (the repo has a `bun.lock`).

- `bun install` — install dependencies (`postinstall` runs `nuxt prepare`)
- `bun run dev` — dev server at http://localhost:3000
- `bun run build` / `bun run preview` — production build / preview
- `bun run lint` / `bun run lint:fix` — ESLint (`@nuxt/eslint`)
- `bun run test` — run all tests once (Vitest)
- `bun run test tests/components/HeroSection.spec.ts` — run a single test file
- `bun run test:watch` — watch mode
- `bun run test:coverage` — coverage report (thresholds must pass)

## Architecture

### Components

Two layers under `app/components/`:

1. **Top-level section components** (`HeroSection.vue`, `BenefitsSection.vue`, `PricingSection.vue`, etc.) — the units listed in `app/app.vue` and the ones covered by tests.
2. **Nested presentational subcomponents** in folders named after their section (`Benefits/`, `Contact/`, `Features/`, `OurPurpose/`, `Pricing/`, `WhoWeAre/`) — background, title, card, and illustration pieces composed by the section component. These folders are deliberately excluded from coverage.

### Internationalization

Custom i18n — **not** `@nuxtjs/i18n`. `app/composables/useI18n.ts` wraps `i18n-js` with translations loaded from `locales/en.json` and `locales/es.json`. Locale is shared app-wide via `useState('i18n-locale')`, detected from the `Accept-Language` header on the server and `navigator.language` on the client, falling back to `en`. Only `en` and `es` are supported. Add new strings to both locale files; `tests/translations.spec.ts` covers the locale files.

### Testing

Vitest + Vue Test Utils + jsdom, configured in `vitest.config.ts` (not through Nuxt). `vitest.setup.ts` stubs Nuxt globals (`useState`, `useRequestHeaders`, `useI18n` — its `t()` returns the key itself) and exports `globalStubs` (`NuxtLink`, `NuxtImage`) to pass as `global: { stubs: globalStubs }` when mounting. Aliases `~` and `@` resolve to `app/`.

Coverage requires **80%** lines/branches/functions/statements, measured only over top-level `app/components/**` and `app/composables/**` (nested section subfolders excluded). Tests live in `tests/components/` and `tests/composables/`.

### Performance tuning in nuxt.config.ts

`nuxt.config.ts` carries deliberate performance work — be careful when touching it:

- Inline critical CSS in `app.head.style`, plus a `nitro` `render:html` hook that injects a script deferring the `_nuxt/entry` stylesheet (media=print swap).
- `@nuxt/image` uses `provider: 'none'` — `<NuxtImage>` does not transform images; optimized variants live pre-built in `public/images/`.
- Font/hero-image preloads and async font CSS loading are in `app/app.vue`'s `useHead`.
- `routeRules` set immutable cache headers for `/fonts/**`, `/images/**`, `/_nuxt/**`.

## Notes

- Never edit or commit `.nuxt/` autogenerated files.
- `pencil.pen` is an encrypted pen.dev design file — access it only through the pencil MCP tools, never with Read/Grep.
- `scripts/generate-favicon.js` regenerates favicons.
- Docker: `docker-compose up` for local dev with volume mounts; `Dockerfile` uses Node 21.
